# Godly Inspiration

Godly (godly.design) est une galerie curatée des meilleurs travaux de design web, app, UI et visuel publiés sur internet. Ce n'est **ni un outil ni une librairie de composants** — c'est une source de références visuelles à consulter avant de concevoir, pas quelque chose qu'on installe dans un projet. Cette skill s'utilise en amont, à l'étape de cadrage, avant d'écrire la moindre ligne de code ou le moindre design.

## Quand la consulter

Dès qu'une tâche implique de concevoir ou repenser une interface et qu'il manque une direction visuelle claire : nouveau site vitrine, landing page, refonte d'un projet existant (portfolio, Geodemy, plateforme environnementale, etc.), identité visuelle, ou simplement quand Morija dit vouloir "quelque chose de bien", "comme sur tel site", ou demande de l'inspiration.

## Comment l'utiliser

Godly organise ses références par catégorie — aller chercher directement la catégorie pertinente pour la tâche plutôt que de parcourir la page d'accueil généraliste :

- **Websites** — sites complets, pour une direction d'ensemble (mise en page, ton, densité).
- **App Screenshots** — interfaces d'applications, utile pour un dashboard ou un outil (mode "Operate").
- **App Icons**, **Logos** — identité visuelle et icônes.
- **OG Images** — images de partage social.
- **Hero**, **CTA**, **Footer** — sections isolées, idéal quand seul un fragment de page pose problème (ex: "mon hero est fade", "mon footer manque de personnalité").
- **Trending** — ce qui émerge actuellement, utile pour vérifier qu'une direction ne semble pas déjà datée.

La recherche intégrée (raccourci ⌘K sur le site) permet de cibler un style ou un secteur précis si les catégories générales ne suffisent pas.

## Méthode de travail

1. **Identifier le fragment à sourcer** : page entière, ou une section précise (hero, CTA, footer) selon ce qui pose problème.
2. **Aller chercher 3 à 5 références** dans la catégorie correspondante (via la recherche web ou un navigateur) plutôt qu'une seule — une référence unique mène à une copie déguisée, plusieurs références permettent de dégager un principe commun (structure, hiérarchie, ton) à adapter plutôt qu'à reproduire.
3. **Extraire le principe, pas le décor** : noter ce qui fonctionne structurellement (rythme, contraste, hiérarchie de l'information) plutôt que des détails superficiels à copier tels quels (une police précise, une couleur de marque qui n'est pas celle de Morija).
4. **Cadrer la direction** avant de construire : résumer en une phrase la direction retenue (éventuellement avec le mode Persuade/Operate/Read/Experience de la skill **impeccable-design**) pour que le reste du travail s'y tienne.

## Suite du flux de conception

Godly fournit la **direction** (quoi viser), pas l'exécution. Une fois la référence choisie, enchâiner naturellement avec :
- **impeccable-design** pour éviter que l'exécution retombe dans les anti-patterns "AI slop" en essayant de reproduire un style trouvé sur Godly.
- **aceternity-ui** si le projet est en React/Next.js + Tailwind et qu'un composant animé prêt à l'emploi peut concrétiser rapidement la direction trouvée (hero, background, carte, navigation).

Ne jamais présenter une référence Godly comme le produit final : elle sert à nourrir une proposition originale pour le projet de Morija, pas à la remplacer.
